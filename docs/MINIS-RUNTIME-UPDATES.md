# OpenCode / ZCode 核心维护

客户端自带已验证的离线核心作为兜底。当前打包版本为OpenCode 1.18.3、ZCode CLI 0.16.9、Node 24.18.1；不是把最新桌面版本直接搬进Android，也不代表官方免费额度接入完成。

在Minis内置终端使用：

```sh
minis-clients status          # 实际核心版本
minis-clients runtime-status  # 当前/前一个托管目录
minis-clients check-update    # 检查已通过适配验证的版本
minis-clients update          # 下载、验证、安装并切换
minis-clients rollback        # 切回前一个健康核心
```

更新由用户触发，不自动追随上游latest。新版本需维护者验证并发布独立签名清单，无需每次重新下载整个APK。托管入口会阻止已知的直接CLI自升级命令；用户自己安装的命令保留。已运行的托管任务持共享锁，更新/回退要求独占锁，忙时停止并提示重试。不会结束正在执行的任务。

## 信任与安装

清单固定在本站HTTPS，独立RSA公钥内置APK，私钥留在受控发布环境。严格校验签名、有效期、架构、最低宿主版本、适配器/数据格式、包摘要和长度，拒绝重定向及较旧发布序号。同序号不得替换成不同内容。APK更新可轮换受信任公钥；网络清单不能自行指定新公钥。

运行包先下载到临时文件，校验全部tar成员、相对链接、展开规模，再解到独立目录；不执行下载包中的安装脚本。OpenCode/ZCode的版本启动检查通过后，先保留私有配置/登录与数据目录的恢复副本，再原子切换指针。旧目录和APK内置核心保留，验证失败时当前指针不变。

## 数据与兼容边界

运行文件与用户home分开。备份位于应用私有的 `/opt/minis-clients/data-recovery`，不进入公开分发或账号技能包。回滚只切核心，不覆盖用户后来产生的数据；数据副本用于人工恢复。当前发布只允许数据格式不变的版本；数据库或登录格式变化、主版本升级必须单独适配和迁移验收，不能仅换二进制就声称可回滚。更新不替代第三方账号授权。

未自动删除旧核心或恢复副本；低空间时更新停止，原内容保留。共享锁只约束托管入口，用户自行绕开启动的进程不受管理。原版CLI自身的会话与Minis共享会话不是同一协议。

## 发布维护

`scripts/prepare_runtime_release.py` 从经验证、不含用户配置的官方资源包生成不可变包与签名索引。未来更新需重新核验官方来源/许可、版本启动、对话/流式结果、工具、取消续跑、个人设置及账号授权，再签发更高序号。独立更新器不能保证上游免费权益不变。
