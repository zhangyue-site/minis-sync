# 开发交接排版规范

默认使用Markdown，不再把所有字段挤成连续段落。滴答保存短版，仓库保存完整版；不依赖HTML、颜色或折叠组件。即使客户端没有渲染Markdown，短标题、空行、勾选和状态词也应可直接阅读。

## 统一语法

- `# 项目｜交付目标`：一份交接一个一级标题。
- `> 🟡 进行中 · 更新：日期时间`：第一屏给出状态、时间及一句结论。图标只作辅助，必须保留文字。
- `## 现状 / 已完成 / 待处理 / 验证 / 下一步 / 接力入口`：二级标题分区，不使用深层嵌套。
- `- [x]` 只标有证据的完成项；`- [ ]` 标剩余工作。它们是正文标记，不代表勾选滴答任务或修改子项。
- **粗体**标关键结论、阻塞或限制；文件、命令、分支用行内代码；可执行的多行命令用带语言的代码块。
- 仓库用Markdown链接定位代码与日志入口。滴答用可打开的GitHub文件链接；不粘贴凭据或大段原始日志。
- 验证对比可用三列表格；手机滴答优先短项目符号，避免横向滚动。没有实测就写“未验证”，不能用“✅”掩盖范围。
- 状态词：⚪ 待开始、🟡 进行中、🧪 待验证、🔴 受阻、✅ 已完成、⏸ 暂停。颜色不作为唯一信息。
- 历史内容放当前结论之后，标题明确“历史记录”，不让旧状态和当前状态并列争抢第一屏。

## 滴答短版

```markdown
## 🟡 进行中｜项目与交付

**现状：** 已实现什么；还不能使用什么。

### 已完成

- [x] 已完成事项（证据与时间）。

### 待处理

- [ ] 剩余事项。
- [ ] **阻塞：** 具体原因及解除条件。

### 下一步

1. 先打开哪个文件或执行哪个动作。
2. 看见什么结果才算通过。

**接力入口：** 仓库链接、分支、交接文件链接。
**更新：** 时间、实际工具/会话、稳定任务键。
```

## 仓库完整版

```markdown
# 项目｜交付目标

> 🟡 进行中 · 更新：日期时间
>
> 一句话说清现在能做什么、还缺什么。

## 已完成

- [x] 事实与证据。

## 待处理

- [ ] 剩余交付。
- [ ] **阻塞：** 具体缺口。

## 验证

| 检查 | 结果 | 证据或限制 |
| --- | --- | --- |
| 功能测试 | 通过 / 失败 / 未运行 | 环境、命令和时间 |

## 下一步

1. 可执行的第一步。
2. 明确验收条件。

## 接力入口

- **代码：** 仓库、分支、已核实的提交。
- **当前执行：** 实际工具/会话及负责范围。
- **工作区：** 未提交文件、其他会话分工、仍在运行的操作。
- **绑定：** 稳定任务键及已授权环境中的任务ID；共享文档不含私人绑定。

## 历史记录

保留有价值的旧决策、失败尝试与回退入口；注明它们属于历史。
```

简单交接可缩减没有内容的区块，不机械保留空标题或填写无意义百分比。
