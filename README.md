# Minis 同步版

基于 Minis 上游 APK 的 Android 同步补丁、配套服务端及开发交接扩展。目标是让同一账号在多台手机和电脑上共享会话，并恢复自己的技能、配置和 AI 供应商设置。

截至 **2026-10-24**，已核验的线上 Android OTA 为 **1.14.19 / versionCode 120**；服务端安全修复已部署。**这不代表 119 已完成实体手机验收，也不代表 Mac、Windows、iOS 已实现统一会话体验。**

此仓库不是完整的上游 Android Gradle 工程。Android 重打包依赖上游 APK、smali 工具、SDK、运行库及独立管理的签名材料。见 [构建说明](docs/BUILD.md)、[119 源码快照](android/119/README.md)和[服务端安全修复](docs/MINIS-V3-SAFETY.md)。119 快照未在本轮重新构建，不构成可复现 APK 的证明。

## 当前开发版本（服务端已部署，Android 待发布）

`android/client` 是基于 119 的活跃候选源码。121 / 1.14.20 为本轮候选版本，发布前需要重新核对版本。线上 120 已新增会话一致时跳过重复应用和提交失败重试；本轮保留这些同步修复，并保留 NAS 历史备份。下文旧119说明作为历史边界。

| 本轮新增 | 实现与验证边界 |
| --- | --- |
| 双向增量 | 保留上传条目增量；新增 MSD1 下载差量，复用 ZIP 压缩成员内块，按目标 SHA 精确重建。首次下载或无可用差量仍走全量；不属于逐 Token 实时同步 |
| 登录恢复 | 新账号安装首次登录触发恢复，不必等待充电；完成后继续沿用后台调度。首次恢复跳过 NAS 备份，避免引导过程触发额外上传 |
| 私有技能/供应商 | 原生分类导入供应商和可移植 API Key；技能校验后只新增，同路径冲突保留本机与云端恢复件。设备 OAuth、回环供应商与桥接令牌不复制 |
| 应用确认 | 配置证明与聊天 ACK 分开；配置 ACK 不授权聊天删除。有证明的配置基线支持三方合并，省略项不视为删除 |
| 账号边界 | 安装绑定首个账号，切换其他账号时停止同步防止串号；完整多账号本地工作区与退出清理仍待完成 |
| 客户端内置 | 同步核心、基础技能/默认配置及 OpenCode 1.18.3、ZCode CLI 0.16.9、Node 24.18.1；私人凭据从账号恢复。本轮实际版本启动已验证，官方免费额度接入仍后续单独做 |
| 核心独立更新 | 内置公钥验证签名清单，独立目录安装、版本健康检查、私有配置恢复件和原子切换；托管任务锁保护，支持手动检查/更新/回退。Android已从公网完成更新、实际启动与回退；不自动追上游latest |

本机 **103 项后端隔离测试通过**。Android 最终候选已编译并通过两台隔离模拟器验证：新机自动登录恢复真实 Room 会话/消息、私有技能和原生供应商 API Key；第二台新增消息回传第一台；已有密钥保留；切换账号被拒绝。Java 在 Android 上用 776 字节差量精确重建 3,147,254 字节目标。服务端读回两台设备的配置应用证明。此前候选119→120覆盖升级标记保留；尚无实体手机验收。服务端已部署，并验证原有数据表记录未变。两台隔离 Android 经实际公网服务再次验证恢复、双向消息及跨账号资源拒绝。APK仍待本轮正式发布与OTA验收，Mac/iOS成品客户端仍待完成。API Key 随账号私有备份传输和保存，目前**不提供端到端加密或独立设备授权**。

以下是本项目增加或修改的内容；没有逐个审计所有上游版本，不能把每一项都理解为“原版完全没有同类功能”。

| 方面 | 本项目改动 | 当前证据与限制 |
| --- | --- | --- |
| 增量上传 | 首次完整上传；有已应用基线时，比较 ZIP 条目并上传变化条目及删除清单 | 119 代码已包含；属于条目增量，**不是逐消息/Token 增量**。既有基线缺失时停止并保留安全备份，不能笼统写成自动回退全量 |
| 云端合并 | 三方合并、不可变版本、操作幂等、账号隔离、按设备确认应用 | 当前 v3 服务已部署；本轮服务端回归通过 |
| 多设备删除与冲突 | 用已应用基线推断删除；并发修改保留恢复内容 | 服务端仅信任显式 ACK；上传成功不等于设备已应用云端版本 |
| 配置冲突保护 | 会话与其他分类分开处理；配置冲突保存恢复副本 | **119 自动应用仅会话和附件**；技能、供应商等仍保留本机，不是自动配置恢复 |
| 后台自动同步 | 充电且 Wi-Fi 时由系统调度；手动同步不受此条件限制 | 119 已包含相关代码；系统调度并非实时推送，实体设备后台/重启验收待完成 |
| 断线与中断恢复 | 下载断点续传、持久待办、退避重试、同步检查点与完整性校验 | 已包含代码，部分历史隔离验收及本轮服务端测试通过；接收新版本仍下载完整包 |
| NAS 备份 | SMB 临时上传、完整回读 SHA-256 校验后发布最终文件 | 有历史隔离/真实 NAS 备份证据；**不是 NAS 双向同步** |
| 云端归档 | 内容块去重、恢复索引、NAS 历史备份相关模块 | 不等于手机客户端双向增量传输；长期恢复、容量与费用需独立观察，不能承诺固定年费 |

| 服务端清理 | 共享提交锁、完整引用保护、缺基线闭锁、可恢复隔离 | 本轮已部署；不永久删除文件或索引，隔离区也不释放磁盘空间 |
| 恢复与鉴权 | 精确摘要恢复基线、同步前安全备份、账号隔离、鉴权副本过期 | 本轮服务端验证通过；账号隔离不等于端到端加密 |

| 签名与 OTA | 乐天家族签名、版本与摘要校验、重复 DEX 补丁修正 | 有历史签名/隔离升级证据；用户实体手机的 119 覆盖升级尚待验收，不能卸载替代迁移 |

## 三个目标与尚存问题

### 1. 多手机、Mac 等设备共享同一份会话

**当前：部分实现，尚未达到完整产品目标。** Android 与云端已有账号下的统一版本及合并逻辑，但仍以导出备份、上传、下载完整新包、应用为主。

- [x] 服务端会话合并、删除保护、账号隔离、幂等与显式 ACK 有本轮回归证据。
- [ ] 双向增量：目前增量主要用于上传，下载仍是完整版本；修改一个大 JSONL 条目也可能上传整条目。
- [ ] 登录/启动后及时接收变化：现有自动条件要求充电与 Wi-Fi，系统周期任务不能提供即时共享体验。
- [ ] Mac、Windows 成品客户端接入：仓库里的 macOS 可编译 Swift 核心不等于 Mac 客户端；本轮未找到已验收的 Windows 适配。
- [ ] 完整 iOS App 构建、安装及与 Android 双端真机互通。
- [ ] **生产协议与 iOS 候选尚未对齐：** 当前 `server/v3/minis_cloud.py` 仅接受 `all/chats`；iOS 候选 `HTTPTransport.swift` 提交和 ACK 使用 `workspace`。直接连接会被拒绝，不能只解决 IPA 构建就宣称互通；共享工作目录也需单独接入与验收。
- [ ] 明确会话 ID、分支、顺序和删除的跨端语义，并验证并发编辑、离线重连和账号切换。
- [ ] 运行中任务的执行者管理：共享会话历史不会迁移另一台设备上的进程、终端或工具执行状态；需要防止两端重复执行同一任务。

**验收目标：** 同账号两台 Android 与一台 Mac/iPhone 接续同一会话；新增、修改、删除、附件与离线合并一致；新设备首次拉取后，后续传输只包含需要的变化，并量化字节数、同步延迟和恢复行为。Windows 在具备适配及相同验收证据后才能列为支持平台。

### 2. 在 Minis 中使用 ZCode / OpenCode 的官方免费或登录减免额度

**当前：有客户端和代理基础，尚未完成这个效果。** 安装官方 CLI、放入供应商模板、请求返回 HTTP 200，都不能证明 Minis 对话实际使用了预期权益。

- [x] 有官方客户端离线安装及历史 OpenCode 原生运行证据。
- [ ] ZCode 新会话登录、实际推理、工具调用及续跑的完整验收。
- [ ] Minis 对话界面到官方客户端/官方服务的完整路由；现有 `provider_rpc.py` 部分通道使用服务器固定配置，不能据此宣称每个登录账号都使用自己的官方额度。
- [ ] 明确区分免费模型、体验额度、订阅额度、闲时任务、普通付费 API，并显示实际账号与计费通道。
- [ ] 额度用尽、限流、权益变化时明确提示，不静默切到付费 API。
- [ ] 记录真实请求与官方用量变化，证明用了正确通道；官方登录会话需要单独验证可迁移性，不能直接复制设备绑定凭据文件。

官方能力会变化，核对日期为 2026-10-24：

- [OpenCode 官方模型文档](https://opencode.ai/v2/docs/console/models/)说明免费层聊天模型要求通过 OpenCode 使用；普通 API 代理或修改客户端标识不构成权益接入证明。
- [ZCode 官方账号连接文档](https://zcode.z.ai/cn/docs/configuration)区分账号登录与 API Key；[ZCode 官方权益说明](https://zcode.z.ai/cn/docs/welcome)把体验权益与订阅用户的闲时队列分开。闲时免费任务不等于任意实时 API 调用都免费。

**验收目标：** 用户在 Minis 中完成自己的官方账号登录，正常发起对话与工具任务，能核对实际通道和额度变化；免费/减免不可用时可理解地停止或提示，不产生未明确选择的付费回退。

### 3. 私有配置跟随账号，新手机登录后自动就绪

**当前：尚未实现自动恢复。** 119 刻意只应用会话与附件，并在应用后检查本机其他配置未被改写；这是现有保护边界，不能写成已经实现技能/供应商自动同步。

- [ ] 按账号分别存储、版本化和读取技能、自定义指令、记忆、供应商/模型设置；不得混用维护者的默认配置或其他账号的内容。
- [ ] 首次登录到空设备时自动下载并应用；已有本机修改时分类合并，保留冲突和回退，避免全量覆盖。
- [ ] 密钥、API Key 和 OAuth 凭据与普通设置分开处理；定义加密、设备授权、失效与退出清理规则。APK 和 Git 不包含私人凭据。
- [ ] 处理系统差异：配置意图可共享，但 Mac/Android/iOS 的绝对路径、可执行文件和运行依赖不能原样照搬。
- [ ] 账号切换时隔离会话、配置和待办；验证不会把 A 账号的供应商凭据带给 B 账号。
- [ ] 区分 Minis 同步账号登录与第三方官方模型账号授权；无法安全跨设备复用的授权需要重新登录。

**验收目标：** 一台全新设备仅登录 Minis 账号即可得到该账号可移植的技能、设置和供应商列表；能安全提供的凭据按授权恢复，需要重新授权的供应商明确提示。账号切换、断网重试、并发改配置和恢复旧版本均不泄露或覆盖另一账号的数据。

## 后续优先顺序

1. **先定统一数据协议和账号边界：** 会话/附件与私有配置分开版本化，统一应用确认、冲突和设备身份；保留已有数据及恢复入口。
2. **再做会话双向增量与新设备引导：** 用实际大历史、多设备场景量化下载、应用耗时和流量，补 Mac/iOS 成品接入及账号配置恢复。
3. **并行推进官方额度接入的独立验收：** 优先使用官方客户端与正式登录通道；明确实际模型、权益和任务执行位置。不能把此项与普通 API 联通合并验收。
4. **最后完成真实设备组合测试：** 119 升级与后台行为、Android/Mac/iPhone 多端、旧格式和账号切换；候选模块通过后才考虑迁入生产。

这是一份待实现/待验收清单，不代表本轮已经完成上述新增能力。

## 验证记录与范围

- **本轮服务端：** macOS、106 Linux 各 86 项隔离测试通过；GitHub 安全回归通过。包含真实 HTTP → 前端 → RPC → 临时存储的 ACK、合并/删除/重试，以及并发清理、精确恢复、预算和鉴权。
- **本轮线上只读检查：** 匿名 401、测试账号 head 200、Range 206、跨账号摘要 404；缺失基线已恢复至 0。恢复的是验收账号基线；真实账号的版本/设备基线文件已检查完整。切换前后 head、版本、删除记录与回执一致；清理删除/隔离均为 0。
- **历史 Android 证据：** 老版本的隔离升级、双 Android 同步、NAS、交接桥和 OpenCode 开发交接测试。不能代替 119 实体设备或新的多端配置恢复验收。
- **iOS / workspace 候选：** 见 [iPhone 与 Android 候选说明](docs/IOS-SYNC.md)。其中生产迁移等状态属于 2026-10-21 历史记录；当前服务端状态以上述安全修复记录为准。候选测试通过不等于当前已发布客户端支持它。

其他 Android、NAS、iOS 测试需要独立设备/依赖与隔离环境。不得向真实用户数据库或真实手机执行测试夹具。
